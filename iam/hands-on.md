## Step-by-Step Process

### 1. Created an IAM User

- IAM → Users → **Create user**
- Username: `shreya_tambe`
- Enabled: **Provide user access to the AWS Management Console** ✅
- Console password: **Autogenerated password**
- Checked: **Users must create a new password at next sign-in** ✅

> **Why autogenerated?** Best practice — never set a weak manual password for IAM users. Force them to reset on first login.

---

### 2. Created a User Group

- Instead of attaching policies directly to the user → created a **group** first
- Group name: `devops`
- Policies attached to group:
  - `AdministratorAccess` — full access to all AWS services
  - `AIDevOpsAgentFullAccess` — full access to Amazon DevOps Guru (AI-powered ops)

> **Why groups?** AWS best practice. Instead of managing permissions per user, you manage per group. Add/remove users from group → permissions automatically apply.

---

### 3. Set Permissions

- Permissions options explored:
  - **Add user to group** ✅ (selected — best practice)
  - **Copy permissions** — copy from another existing user
  - **Attach policies directly** — not recommended for production
- Added `shreya_tambe` to `devops` group

### 5. MFA Setup

- IAM → Security credentials → **Assign MFA device**
- Device name: `mac_neha`
- MFA options explored:

| Option | Description |
|---|---|
| **Passkey / Security key** | Fingerprint, face, screen lock or FIDO2 key — most secure |
| **Authenticator app** | Code from Google Authenticator / Authy on phone |
| **Hardware TOTP token** | Physical hardware device |

- Selected: **Passkey or security key** (AWS recommended)

> **Why MFA?** Root account or IAM users without MFA = huge security risk. If credentials leak, attacker still can't login without the second factor.

## Key Concepts Learned

| Concept | What it means |
|---|---|
| **IAM User** | Individual identity with credentials to access AWS |
| **IAM Group** | Collection of users — permissions managed at group level |
| **IAM Policy** | JSON document defining what actions are allowed/denied |
| **AdministratorAccess** | Full access to all AWS services — use carefully |
| **MFA** | Multi-Factor Authentication — second layer of security |
| **Autogenerated password** | AWS creates a strong password, user resets on first login |
| **Console sign-in URL** | Account-specific URL: `https://<account-id>.signin.aws.amazon.com/console` |

---

## IAM Best Practices (Industry Standard)

- Never use root account for day-to-day tasks — create IAM users
- Always enable MFA on root account and all IAM users
- Use groups to manage permissions, not per-user policies
- Follow **least privilege principle** — give only the permissions needed
- Never hardcode Access Keys in code — use IAM roles instead
- Rotate access keys regularly
